# MemSpace · 内存管家

一个从零编写的 Windows 内存诊断与按需释放工具。C# + WinForms + Windows 原生 API，运行依赖 .NET Framework 4.8（现代 Windows 10 / 11 通常已包含），无需安装 Python、Node 或其他第三方运行时。

1.3.0 新增自动强力释放、持续识别的自动排除和勾选应用的排除名单，精简页面说明。保留系统强力释放、随窗口重新排布、应用汇总、活动保护、启动项状态与三档字号。默认正文为 13.5 磅，相当于 100% 屏幕缩放下 18 像素。

## 运行

在 [最新版本下载页面](https://github.com/Xushengming222/MemSpace/releases/latest) 下载 `MemSpace-版本号.zip`，解压后双击 `MemSpace.exe`。保留 `MemSpace.exe.config` 与 EXE 在同一目录。普通用户权限即可使用，强力释放时才申请管理员授权。

需要 Windows 10 / 11 与 .NET Framework 4.8。此程序暂未进行代码签名。使用源码时，请按下方构建步骤生成 `artifacts/MemSpace.exe`；GitHub 的 Source code 压缩包是源码，直接运行请下载版本附件中的便携包。

建议先打开“开机排查”，通过 Windows 启动设置关闭不需要的第三方常驻程序；重启后在同样的软件运行条件下比较。“释放后台内存”用于临时缓解压力，无法保证把 10 GB 降到某个指定数字。

## 功能

- 实时显示使用中 / 可用内存、已提交量与上限、非分页池、估算硬件保留和最近两分钟趋势。
- 默认按应用汇总占用，可切换到单个进程，搜索、排序、双击查看完整路径和家族内进程，以及加入排除名单。按可执行文件路径、用户和会话区分应用，并合并同一安装目录下的子进程。
- 一键释放当前用户闲置后台程序的工作集。也可明确选择单个程序释放。
- “强力释放”：手动点击后通过 UAC 启动短时管理员助手，依次回收系统工作集、刷新修改页、清空待机列表。与本地 PCL 2.13.1.1 中分析到的三步操作相同。
- “自动强力释放”：勾选并保存，或点击“授权管理员”。授权成功后，本次运行复用管理员助手，按相同阈值、持续 45 秒和 15 分钟冷却触发，结果写入日志，不弹出结果窗口。两种自动选项都启用时优先使用已授权的强力模式。
- 自动识别常见游戏、录屏、Office、开发与创作软件及其安装目录，在后台释放时保护整个进程家族。新启动的应用也会参与识别。可通过“选择应用”搜索和勾选补充排除，无需填写进程名；原有名单继续保留。
- 常见 Run 注册表项与用户 / 公共启动文件夹列表，显示可识别的 Windows 启用/禁用状态，一键打开 Windows 启动设置和任务管理器。
- 字号提供 100%、125%、150% 三档，保存后立即更新并记住选择；按显示器 DPI 调整文字、控件和绘图，空间不足时可滚动。
- 窄窗口使用顶部菜单，操作按钮换行，信息卡片按三列、两列或单列排列。页面保持窗口宽度，内容向下滚动；排行与启动项的宽列在表格内部横向滚动。更改字号保留当前窗口大小。
- 导出本地诊断报告，包含内存统计、进程排行、启动注册项与解释。
- 点击标题栏最小化按钮或“收起到托盘”会隐藏窗口并显示托盘图标，不保留最小化的任务栏窗口。双击托盘图标或选择“打开内存管家”恢复。关闭主窗口会退出；托盘菜单也可退出。
- 可选自动释放：使用率达到设定阈值，持续至少 45 秒才触发，每次尝试至少间隔 15 分钟。
- 可选登录启动与延迟两分钟的按需释放。登录释放也受阈值和冷却时间约束。

两种自动释放、登录启动和登录后释放**默认关闭**，自动识别排除默认开启。在设置页面勾选后点击“保存设置”生效。自动强力需要本次运行的实际管理员授权，保存勾选状态并不代表已授权；重新打开软件需要再次授权。启动时及高占用触发时不会主动弹出 UAC。取消授权时自动强力保持未授权状态，若同时开启后台自动释放则继续使用后台模式。取消勾选自动强力或退出软件会结束助手会话。新增自启动只写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\MemSpace`，关闭该选项会删除这一项。如 Windows 已在任务管理器中禁用了此项，需在那里重新启用。移动 EXE 后，请关闭再开启登录启动，以更新路径。

## 释放策略及边界

后台释放调用官方 `EmptyWorkingSet`，不结束进程，不停用服务，不关闭内存压缩，不修改分页文件，不申请调试权限，不清空待机缓存。以下逐应用保护规则用于后台释放。

默认保护：系统进程、Windows 目录下的组件、关键进程、无法确认关键状态或归属的进程、其他用户和 Session 0 服务、工具自身、前台及有可见窗口的应用家族、过去两分钟内用过的前台应用家族、排除名单及家族、小于 32 MB 的进程，以及采样期间 CPU 活动超过约单核 2%、有写入操作或读取速度超过 128 KB/s 的程序。无法读取 I/O 活动也会跳过。I/O 计数包含文件、网络等，并非专门的磁盘计数。

家族关系根据父进程 PID、创建时间、用户和会话验证，以避免父进程 PID 复用造成误关联。保护会覆盖同一程序路径的其他实例及不同进程名的子进程；不跨系统启动器继续追溯。最近使用记录只在本次工具运行期间采集。

默认排除包含 Java、OBS、Steam、开发工具、部分创作软件、无畏契约、录屏及 Codex。自动识别结合已知程序名与完整目录段（如 steamapps、Epic Games、Riot Games、Adobe）识别应用，不依靠任意包含 game 的名称猜测。无法完整识别所有软件，也不能恢复已退出父进程的家族关系；可以在选择应用中勾选补充。自动识别形成当前扫描的动态保护，不把检测结果不断写进手动名单。关闭自动识别后，基础前台、近期使用和读写保护仍生效。

“释放选中程序”可包含有窗口的闲置应用，会先说明可能出现短暂卡顿；其他保护规则仍有效。打开进程句柄后会重新验证创建时间、用户归属和关键进程状态，避免 PID 复用误处理。权限不足会跳过或报告失败。

释放工作集会让暂时不用的页离开程序的物理驻留集合。再次访问时可能发生软 / 硬缺页，内存占用可能回升，磁盘较慢时可能卡顿。因此释放前后显示的是**实际采样变化**，其他软件也会影响结果，负变化不会伪装成收益。私有提交量通常不会随工作集释放而下降；这不是修复内存泄漏。

可用内存已包含可回收的待机页，无需为了低数字频繁清空缓存。驱动非分页池、硬件保留和仍在活跃使用的内存不能靠工作集释放解决。

“强力释放”使用 `SeProfileSingleProcessPrivilege` 与 `NtSetSystemInformation` 信息类 80，依次执行操作 2、3、4。系统操作无法遵守应用排除名单，会影响前台及正在使用的应用，可能短暂卡顿并增加磁盘读写。手动操作及已经授权的自动强力模式使用此策略；其他自动释放使用后台策略。常驻界面不需要管理员权限，助手每次操作后恢复令牌权限。仅自动强力授权会话保留空闲助手，关闭选项或退出软件后关闭管道，助手结束循环退出。退出不会撤回已经开始的原生操作。

界面显示执行后 2 秒的实际可用内存变化，逐步报告成功或失败；某一步失败就停止后续步骤，已有成功操作不能撤回，结果会明确标记未全部完成。不同 Windows 版本或权限策略可能拒绝此原生接口。同一负载下的实际收益仍需用户比较，不能保证每次释放 3 GB，或比其他工具更多。程序再次使用数据后，内存占用可能回升。

助手通过仅当前用户可访问的随机命名管道通信，双方验证进程身份；管理员助手不写入用户提供的文件路径。自动会话只接受固定的释放/停止命令，不接收执行路径或系统设置。父进程退出或崩溃使管道断开，空闲助手随之退出。强力步骤失败会停止当前会话，等待用户重新授权，自动触发不会再次请求 UAC。UAC 需要同一用户的管理员授权；切换到其他管理员账号时可能无法连接。

## 诊断限制

工作集包含共享页，各进程工作集之和不能直接等同于系统使用量。私有提交量也不是物理内存。“系统缓存”与“可用内存”不是可直接相加的独立类别。硬件保留为已安装容量减系统可用总容量的估算。

启动状态读取 `Explorer\StartupApproved` 的 Run、Run32 和 StartupFolder 记录，只识别长度至少 12 字节、状态代码为 2 或 3 的常见格式。此格式不是公开稳定的 Win32 契约，未标记、其他代码、无权限或未知格式均明确显示，需在 Windows 设置中核实。列表不涵盖所有服务、计划任务或商店应用，工具不会擅自禁用它们。受保护或无法读取的进程可能不在排行中。

## 数据与卸载

工具不联网。设置写入 `%LOCALAPPDATA%\MemSpace\settings.xml`，每次释放的结果写入同目录的 `activity.log`，日志超过 1 MB 后从头记录。诊断报告只保存在你选择的位置，包含程序名和路径。

卸载时先关闭“登录 Windows 时启动”，保存设置并退出，随后删除发布文件夹即可。可自行删除 `%LOCALAPPDATA%\MemSpace` 下的设置与日志。

## 构建与验证

在项目目录运行：

```powershell
.\build.ps1 -Test
.\package.ps1
```

脚本使用 Windows 自带的 .NET Framework C# 编译器，零 NuGet 依赖。也提供 `MemSpace.csproj`，可用已安装 .NET Framework 4.8 开发组件的 Visual Studio 打开。

自动测试包含保护策略、自动触发与冷却规则、真实内存 API、进程身份与计数器，以及针对专门创建的 96 MB 子进程的真实释放和数据完整性检查。若交互宿主的前台家族保护覆盖这个子进程，验证保护生效后，仅对该测试子进程的已校验句柄直接测试原生释放。不会清理其他应用。

GitHub Actions 在 Windows 上自动检查源码编译和便携包生成；涉及内存回收与界面的检查在本地 Windows 桌面执行。首次发布及后续更新步骤见 [发布说明](docs/发布到GitHub.md)。

1.1.0 另外验证应用聚合、不同用户/路径隔离、父进程 PID 复用、家族与最近使用保护、CPU/I/O 活动、启动项状态、旧设置兼容和字号保存。界面测试覆盖四个页面与三档字号，以及应用/进程视图切换。实际验证的桌面 DPI 为 144；其他显示器的动态切换尚未在实机上验证。

1.2.0 验证系统释放三步顺序、权限失败、取消、部分失败中止与错误码、负变化显示，以及真实助手管道通信。系统操作的分支测试采用替身，不会在开发测试中清空用户的系统工作集或缓存，尚未对实际释放容量做对照测试。界面回归覆盖四个页面、三档字号、五种客户区大小（280×240 到 1500×900）、缩小后再放大、边界、页面底部滚动以及最小化到托盘和恢复。受限沙箱可能禁止子进程连接命名管道，完整助手测试应在普通 Windows 桌面终端运行。

1.3.0 追加复用授权会话的多请求通信、关闭管道后助手退出、未授权与未勾选时禁止自动强力、两种自动模式优先级、识别目录边界和应用家族、排除勾选保留旧名单，以及新增偏好序列化。界面检查还覆盖三档字号下的应用搜索/勾选窗口、授权状态显示与关闭复选框结束会话。通信测试使用专用探针，探针不调用系统内存操作；开发测试未真正触发自动强力清理。

## 来源

灵感来源：龙腾猫跃的 [Plain Craft Launcher](https://github.com/Meloong-Git/PCL) 内存优化入口。PCL 的公开 [PageOtherTest.xaml.vb](https://github.com/Meloong-Git/PCL/blob/main/Plain%20Craft%20Launcher%202/Pages/PageOther/PageOtherTest.xaml.vb) 没有包含百宝箱实现，因此本项目未复制该功能代码，也不属于 PCL 的官方产品或移植版。

根据用户提供的本地 PCL 2.13.1.1 EXE 完成了只读 IL 分析，见 [PCL 内存优化分析](docs/PCL内存优化分析.md)。分析工具只读取程序集元数据和字节码，没有执行 PCL 或其内存优化，也未修改原 EXE。1.2.0 根据这些已确认的原生调用独立实现了同类型的系统级强力释放，没有复制 PCL 程序码。

Windows API 依据：[EmptyWorkingSet](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset)、[Working Set](https://learn.microsoft.com/en-us/windows/win32/memory/working-set)、[GetPerformanceInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getperformanceinfo)、[GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)、[IsProcessCritical](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-isprocesscritical)。
